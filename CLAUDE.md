## Что это за бизнес
- Магазин в Telegram (мини-приложение + бот) под брендом **RAMP**. Цены в сумах, интерфейс на русском.
- Товары — с китайского маркетплейса Пиндодо (Pinduoduo). Выкуп и доставка — через карго-партнёра владельца.
- Курируемый каталог (цель 150–200 товаров) + **поиск по фото**: клиент присылает фото, админ находит товар и отвечает ценой.
- Оплата 100% вперёд (после оформления менеджер присылает реквизиты). Отмена с возвратом — до выкупа в Китае.
- Таможня Узбекистана: курьерские посылки беспошлинно до $200/мес на получателя (пересматривается) — посылки оформляются на самого клиента.

## Безопасность (важно)
- **Токен бота НЕ в коде.** Хранится в таблице `settings` (key `bot_token`). Env `BOT_TOKEN` (если задан) имеет приоритет.
- Все таблицы с RLS. Публично читается только `products` (политика: `active = true`). Всё остальное — только через Edge Functions с service role.
- Каждый запрос из мини-эппа/панели несёт заголовок `x-init-data` (Telegram initData); сервер проверяет HMAC через токен бота (`verifyInitData`).
- Админ-доступ: Telegram ID из таблицы `admins` (+ env `ADMIN_ID`, если задан). Сейчас три админа.
- Секрет вебхука выводится из токена (`webhookSecret()`), бот проверяет заголовок `x-telegram-bot-api-secret-token`.
- Цены и скидки считаются **на сервере**, клиенту не доверяем.
- Токен бота однажды был отправлен в чат — рекомендовано сделать `/revoke` в @BotFather и записать новый в `settings`.

## База данных (основное)
- `products` — каталог (`active` = показывать, `in_stock` = в наличии).
- `profiles` — пользователи: `telegram_id` PK, `public_id` (RAMP-123456, триггер `gen_public_id`), `tg_phone` (подтверждён через Telegram), данные доставки, `referred_by`, `ref_rewarded`, `catalog_view`, `note` (заметка админа), `blocked`.
- `cart_items`, `wishlist` — корзина и «желаемое».
- `orders` — `items` jsonb (копия цен на момент заказа), `subtotal`, `discount_pct/amount/reason`, `coupon_id`, `total`, `status`, `payment_method`.
- Статусы: `new` → `paid` → `bought` → `shipping` → `arrived` → `delivered`, плюс `cancelled`.
- `coupons` — разовые купоны (`ref_inviter`, `ref_invitee`, `manual`), `used_order_id` = использован.
- `photo_requests` — фото в приватном бакете `requests`, ответ админа.
- `settings` — `bot_token`, `promo`, `payments` (редактируются из админки).
- `admins`, `admin_messages` (какое сообщение у какого админа = какой заказ/заявка, для ответа свайпом).
- Устаревшее, не используется: `bonus_balance`, `rank_discount`, `ref_discount`, `bonus_used`, `ref_bonus_paid`, `bonus_refunded`, `add_bonus()`, `orders.admin_message_id`, `photo_requests.admin_message_id`.
- Бакеты: `products` (публичный, фото товаров), `requests` (приватный, фото заявок; ссылки подписанные).

## Бизнес-правила скидок (текущие, утверждены владельцем)
- Рангов и бонусов НЕТ (были, владелец попросил убрать).
- Новичок: −10% на все заказы первые 30 дней с первого входа.
- Рефералка: друг приходит по ссылке `t.me/<бот>?start=ref_RAMP-XXXXXX` или вводит ID до первого заказа.
  Когда друг **оплатит** заказ (статус paid или дальше) с суммой товаров ≥ 200 000 сум →
  пригласивший получает купон −33% на один заказ, друг — купон −11% на следующий. Один раз на друга.
- Скидки **не складываются**: применяется наибольшая. Купон тратится на один заказ, при отмене заказа возвращается.
- Все числа меняются в админке (таблица `settings.promo`), дефолты — `DEFAULT_PROMO` в common.ts.
- Решения, которые я принял сам и владелец ещё не подтвердил: «первое время» = 30 дней; купоны разовые; купон выдаётся после оплаты, а не оформления; скидки не суммируются.

## Что умеет сейчас
**Покупатель (мини-эпп):** каталог (поиск, категории, плитка/список), карточка товара, «желаемое» (в т.ч. для товаров не в наличии), корзина, оформление (выбор оплаты, расчёт скидки сервером, обязательный подтверждённый телефон через `tg.requestContact`), заказы со статусами, поиск по фото (загрузка + история ответов), профиль: RAMP-ID, текущая скидка, купоны, приглашение друга, данные доставки, вид каталога, способы оплаты. Админам в профиле видна ссылка на панель.

**Бот:** `/start` — профиль, ID, запрос номера телефона кнопкой; обработка `ref_`-ссылок; `/myid`; `/admin` для админов. Уведомления клиенту о статусах. Админам приходят новые заказы (с кнопками статусов) и фотозаявки; ответ свайпом уходит клиенту.

**Админ-панель:** сводка, заказы (поиск, фильтр, статус, правка, сообщение клиенту), товары (CRUD, загрузка фото, наличие/скрытие), клиенты (поиск, вся информация, заказы, кто пригласил, купоны: выдать/удалить, заметка, блокировка, сообщение), заявки по фото (ответ), настройки (скидки, способы оплаты, админы).

5. Владелец упоминал «залить на сервер» — уточнить, нужен ли свой VPS/домен (сейчас всё на Vercel + Supabase).

## Как работать в Claude Code
- Подключи Supabase MCP (или CLI с `supabase login`) к проекту `wtfeujuyklteisnrqksl`.
- Деплой функций: `supabase functions deploy api --project-ref wtfeujuyklteisnrqksl --no-verify-jwt` (так же `bot`, `admin`). Общий модуль `_shared/common.ts` подтягивается сам.
- Новые изменения схемы — новым файлом в `supabase/migrations/`, затем применить (MCP `apply_migration` или `supabase db push`). После DDL — проверить security advisors.
- Фронтенд: правишь `index.html`/`admin.html` → commit → push в `main` → Vercel выкладывает сам.
- Проверка синтаксиса без Deno: вырезать `<script>` и `node --check`; для `.ts` — `node --experimental-strip-types --check`.
- Скриншоты: Playwright + Chromium, мокать `telegram-web-app.js` (объект `window.Telegram.WebApp` с `initData`) и ответы `functions/v1/*`.
