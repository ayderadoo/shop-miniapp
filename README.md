# RAMP v4 — избранное, темы, приглашения и истории

Обновление от 21.10.2026. Основной бот @ramp_uzbot, канал @ramp_uz, админский бот @ramptr_bot. Сервер опубликован в проекте `wtfeujuyklteisnrqksl`: **bot v13, api v10, admin v6**. Миграция `20261021134811_stories_and_referral_links.sql` уже применена.

## Обновление с телефона

Распакуйте **RAMP-v4-mobile.zip** и замените в корне существующего GitHub-репозитория только `index.html` и `admin.html`. Не удаляйте остальные файлы. ## Что изменилось

- **Избранное:** сердечко меняется сразу, без ожидания сети. SVG окрашивается фирменным цветом, добавлены короткая анимация и кольцо. Карточки каталога не пересоздаются при каждом нажатии. Добавление/удаление в самом избранном тоже плавное, настройка уменьшения движения учитывается.
- **Сохранение:** новый API wishSet задаёт абсолютное состояние вместо переключения. Запросы по одному товару идут последовательно, разные товары сохраняются независимо. Быстрые нажатия сохраняют последнее желание пользователя; старые ответы профиля не откатывают новое действие. При ошибке последней записи возвращается подтверждённое состояние и показывается уведомление. Ожидание записи ограничено 15 секундами.
- **Статус «Собирается»:** заменяет видимое название «Выкуплен в Китае» в магазине, админке и уведомлениях. Внутреннее значение bought сохранено для старых заказов, правил переходов и статистики.
- **Личный ID:** в профиле и боте показывается один прежний постоянный ID для заказов вида RAMP-D000001 и кнопка копирования. Ручной ввод ID друга и отдельные реферальные ID убраны из интерфейса, админки и выгрузок.
- **Приглашения:** в профиле есть отдельная кнопка копирования ссылки, экран условий и кнопка «Поделиться». Новые ссылки используют случайный токен `?start=invite_...`, отдельный от ID заказов. Старые уже выданные ссылки продолжают работать. Старое служебное поле public_id и реестр сохранены в базе для совместимости; пользователю они не показываются. Купоны и условия бонусов не менялись.
- **Светлая / тёмная тема:** значок луны/солнца в шапке, переключатель в профиле и значок в админке. Выбор сохраняется на устройстве и применяется при следующем открытии; он общий для магазина и панели на одном адресе. Исходная тема светлая. Цены синие в светлой теме и белые в тёмной; важные поля, карточки и кнопки имеют фирменные границы.
- **Истории вместо новостей:** на главной круглая лента с фото/видео. Полноэкранный просмотр с прогрессом, переходами, паузой и звуком. Фото показывается 5 секунд, видео — до окончания; пауза и уход приложения в фон приостанавливают воспроизведение. Истёкшая история исчезает даже при открытом проигрывателе. Опубликованная лента читается со всеми страницами.

## Как добавить историю

Админка → **Контент → Истории → Добавить историю** → **Фото** или **Видео**. До пяти файлов, фото после сжатия до 5 МБ, MP4/MOV/WebM до 25 МБ. Подпись и текст необязательны, загрузка идёт прямо в приватное хранилище.

Срок по умолчанию — **24 часа**. Доступны 1/6/12/24/48 часов, 7 дней и **«Пока не уберу»**. Постоянная история остаётся до снятия флажка «Показывать покупателям» или удаления. Фильтры: все, активные, истекшие, скрытые.

Срок начинается с публикации. Изменение подписи не продлевает его. Изменение длительности или повторная публикация после истечения/скрытия начинает новый срок. Истёкшие записи и их файлы остаются для редактирования и повторной публикации; скрытие не удаляет файлы. Доступные ранее новости сохранены без срока, новые истории требуют фото/видео. Публичная выдача отсекает скрытые и истёкшие записи по времени базы данных; подписанные ссылки на файлы ограничены оставшимся сроком истории (не более часа).

Отзывы с источниками и редактор документов остаются во вкладках Контента. Юридические документы по-прежнему являются закрытыми черновиками до заполнения реквизитов и публикации владельцем; детали в предыдущем разделе v3 ниже.

## Где находятся новые функции

- **Новости:** админка → Контент → Новости → Добавить новость. Заголовок, текст с абзацами, фото/видео, предпросмотр текста, порядок, закрепление. Чтобы новость появилась на главной, включите «Опубликовать на главном экране». Пока опубликованных новостей нет, блок скрыт.
- **Отзывы:** покупатель может оставить отзыв о магазине с главной страницы или о товаре из его карточки. Оценка, текст, фото/видео. Админка → Контент → Отзывы → На проверке → Опубликовать / Скрыть. Изменённый отзыв проверяется снова.
- **Видео/фотоотзыв магазина:** Контент → Отзывы → Фото / видеоотзыв. Можно выбрать товар, имя автора, оценку и файлы. Такие отзывы помечены «Опубликовано магазином»; они не выдаются за проверенную покупку.
- **Вложения:** до пяти на публикацию. Фото после сжатия — до 5 МБ, видео MP4/MOV/WebM — до 25 МБ. Загрузка идёт прямо в приватное хранилище, а не через JSON функции. В опубликованные записи попадают только завершённые загрузки нужного владельца. Для просмотра используются временные ссылки.
- **Артикулы:** Товары → карточка товара → Артикул. Артикулы уникальны без учёта регистра. Они сохраняются в составе заказа, даже если товар позже переименован. Поиск по артикулу работает в товарах и заказах.
- **Параметры:** в карточке товара готовые наборы размеров одежды/обуви, длины, объёма, цвета и произвольные параметры. Названия, варианты, доплаты и описание редактируются в админке; изменения кода не нужны.
- **Учёт ID:** Клиенты → Реестр выданных ID. Старые RAMP-ID для рефералов сохранены. Каждому профилю присвоен постоянный отдельный ID доставок вида RAMP-D000001. Выданные идентификаторы записываются в отдельный реестр и не меняются.
- **Доставка:** ID виден клиенту в профиле и заказах. В карточке заказа администратор вручную задаёт трек-номер и комментарий; клиент видит их в «Заказах». Интеграция с перевозчиком не подключена.
- **Номер:** только собственный контакт Telegram с номером +998 и девятью цифрами после него. Чужой контакт, номер другой страны и неправильная длина не подтверждают регистрацию. Проверка есть в боте, API и транзакции оформления. Старые иностранные номера тоже не дают доступ к действиям магазина. Админская панель по-прежнему защищена списком администраторов и не требует клиентской регистрации.
- **Excel/CSV:** в дополнение к прежним разделам есть «Реестр ID», «Закупка», «Новости», «Отзывы». «Закупка» — отдельная строка на позицию заказа: артикул, параметры, количество, цена и ID доставки. CSV импортируется с разделителем `;`, UTF-8.

## Проверки

`npm test` (Node 24+) — синтаксис HTML/JS/TS и шесть тестов бота/валидации. Оба SQL-набора `tests/database.sql` и `tests/content-database.sql` пройдены, второй также под ролью service_role. Тестовые строки и файлы-метаданные откатываются; последовательности ID могут иметь пропуски. Реальные профили и старые ID сохранены.

Браузерные наборы `tests/browser.py` и `tests/content-browser.py` проверяют магазин, быстрые изменения корзины, оформление, Excel/CSV, новости, безопасность текста, загрузку фото/видео, модерацию, параметры, артикулы, ID и отказ иностранному номеру. Ответы Telegram/API и загрузки в этих тестах изолированы. Новый набор проверен также на готовых двух файлах мобильного архива. Реальная отправка отзыва в Telegram требует обновлённого интерфейса; чужим пользователям тестовые сообщения не отправлялись.

Supabase Security Advisors: ошибок и предупреждений нет. Информационные сообщения «RLS без политик» ожидаемы у закрытых таблиц, доступных только серверу ([пояснение](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy)).

## Для разработки

- npm test
- python -m http.server 8765 --bind 127.0.0.1
- PLAYWRIGHT_BROWSERS_PATH=/tmp/ramp-playwright python tests/browser.py
- PLAYWRIGHT_BROWSERS_PATH=/tmp/ramp-playwright python tests/content-browser.py
- python scripts/build_mobile.py --output /workspace/output/mobile-v2 --archive /workspace/output/RAMP-v2-mobile.zip

Для браузерных тестов нужны Python Playwright, Chromium, openpyxl; адрес меняется через RAMP_TEST_URL. При обновлении серверного общего модуля публикуйте api/admin/bot вместе. Все функции проверяют подпись Telegram; admin дополнительно проверяет разрешённый Telegram ID. Секреты ботов хранятся только на сервере. Новые таблицы и RPC закрыты для anon/authenticated, публикации и файлы выдаются через проверенный API. `order_procurement` использует security_invoker.

Миграция `content_skus_and_delivery_ids` уже применена в рабочем проекте. Повторно применять её сейчас не нужно.
